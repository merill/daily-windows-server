Failover Cluster Manager

14 November 2026Doc update+9 / −7 lines

In brief

The procedure now scopes KB5072033 to every server joining the cluster and replaces checks of FaultDomainAwareness with FaultDomainAwarenessDefault. It also clarifies the storage pool version 29 or later requirement.

What Windows Server admins need to know

When following the campus-cluster setup procedure, use the revised property and PowerShell command and validate the update on all participating servers.

Prerequisites

  • Windows Server 2025 or later with the 2025-12 security update (KB5072033) installed on every node inserver that will be part of the failover cluster.
  • All-flash capacity drives of the same type on every node (SSD or NVMe). Don't use HDDs and don't configure a caching tier.
  • An equal number of nodes in each of the two rack-level fault domains. For supported node configurations, see Failover Clustering topologies. This article shows the 2+2 configuration.
  • Exactly two rack-level fault domains, with cluster nodes spanning both racks.
    Get-StoragePool S2D* | Update-StoragePool

    -ClassName MSFT_StoragePool `
    -Filter 'IsPrimordial = false').CimInstanceProperties['Version'].Value

  2. Verify that the storage pool's FaultDomainAwarenessFaultDomainAwarenessDefault property has the value StorageRack. This value confirms that Storage Spaces Direct places data copies across the two rack fault domains:

    Get-StoragePool -FriendlyName S2D* | Format-List FaultDomainAwarenessFaultDomainAwarenessDefault
