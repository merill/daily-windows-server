Connect Visual Studio Code to a Windows Server Token factory endpoint

18 November 2026Feature update+18 / −19 lines

In brief

The article now covers connecting a Windows client to an existing Windows Server Token factory endpoint. It removes same-device scenarios and adds requirements for network reachability, DNS, trusted TLS, and HTTPS.

What Windows Server admins need to know

Administrators must ensure the endpoint is already deployed and that network, DNS, and certificate configuration permit client access. No action is required solely because of this documentation change.

  • Download the current stable release of Visual Studio Code, and ensure that you can access the Chat view.

  • For a remote endpoint that uses a host name, aA Domain Name System (DNS) record that the Windows 11 client can resolve to the Windows Server host.
  • For a remote HTTPS endpoint, aA valid TLS certificate that the Windows 11 client trusts and whose subject name or subject alternative name matches the host name in the endpoint URL.
  • Endpoint access controls that permit the Windows 11 client to call the Chat Completions route. Obtain any required API key or token from the endpoint administrator.
  • For same-device inference, the loopback URL that the endpoint exposes, such as http://localhost:<port>/v1/chat/completions.
  • For remote inference, aA trusted HTTPS URL, such as https://<server-name>:<port>/v1/chat/completions.

You don't need a GitHub account or a GitHub Copilot plan to use a bring-your-own-key model in chat. The custom endpoint doesn't provide features that depend on the GitHub Copilot service, including inline suggestions, semantic search, and embeddings.
